# 2026-07-20 Editor search-then-scroll no longer snaps back to the match

- Completed and removed `DOIT.editor-search-scroll-snapback.md`. Searching in an editor and then scrolling away used to snap the view back onto the search match on the next passive refresh. Root cause was passive rerenders re-dispatching a SAVED `{anchor, head}` (parked on the match) while a separate rAF scroll-restore raced CodeMirror's synchronous reveal. Fixed by routing every passive path (unfocused rerender, focus re-apply, changed-document sync, locale reconfigure) through one shared owner, `preserveFileEditorPanelPassiveViewState` (`86_changes_editor.js`), which treats the live cursor/selection/scroll as authoritative and never replays a saved anchor; only `{restoreFresh}`/`{restoreFocused}` (fresh reopen / explicit disk replacement) replay saved state, and they do so atomically with a fresh `view.scrollSnapshot()` effect in the same transaction instead of a deferred restore. `updateCodeMirrorViewPreservingState` (`92_codemirror_editor.js`) now folds the scroll snapshot into the same dispatch as its selection fallback (no rAF race, no `scrollIntoView` effect on passive dispatches). Negative search confirmed no passive/refresh path seeds a `requestFileEditorLineTarget` for the match line, so explicit go-to-line / terminal-file-reference / next-prev navigation and reopen-at-saved-line still scroll to target. Net source change +20 lines (88 ins / 68 del across `86`/`92` + two test files) — the fix consolidates divergent per-caller scroll restores into one parent.
