# 2026-07-08 Bounded Quick Open indexing

- Completed and removed `DOIT.240mb_search_index_dilemma.md`. Quick Open now caps each root at a configurable 100,000 in-memory entries, reports oversized roots as explicit partial coverage, excludes generic generated/dependency/build trees plus configured absolute subtrees, and preserves the legacy default disk signature for old readers and writers.
- Queries only consume ready or stale data. The elected filesystem watcher coalesces changed paths, incrementally replaces affected subtrees, and independently schedules the configurable 30-minute full safety scan. Recoverable SQLite persistence is optional, capped by files and bytes, and debounced for 60 seconds; manual tombstones and durable user/settings data keep their existing owners.
- Runtime reports now use the live owner control path and expose build/full/incremental counts, duration, scanned/ignored entries, truncation, dirty subtrees, cache bytes, and write bytes. Focused suites passed (109 persistence/settings/background tests and 75 owner/runtime tests), the final canonical gate passed, and live port 7773 indexed 83,923 Dynamo files once with zero rows from the configured excluded subtree before holding build/write counters unchanged for more than the former 120-second TTL.
- Removed personal and backup-specific names from the repository defaults. Machine-specific Quick Open exclusions now live only in each machine's local `file_explorer.index_exclude_paths` setting; the shared default keeps only generic generated, dependency, and build directories.
