# YO!agent

## DOIT.66/67 YO!agent skills, watches, controlled sends, and coordination audit
- Completed and removed `DOIT.66.md` and `DOIT.67.md`. YO!agent now has built-in YOLOmux skills/context plus user-local overlays in `~/.config/yolomux/skills.d/` and `~/.config/yolomux/context.d/`, with admin-only APIs and chat intents to list, read, write, update, disable, and delete user-local skill/context files. `docs/YOAGENT.md` documents the schema, locations, examples, and management commands.
- Added the first persisted YO!agent job layer. Jobs live in YOLOmux state under `yoagent_jobs`, survive server restart, dedupe by hashed idempotency key, support one-shot notify-session-idle, notify-all-idle, and wait-then-send workflows, expose list/create/confirm/cancel APIs, poll from the existing client-event loop, debounce ready states, timeout once, fire toasts/browser notifications, and publish `yoagent_jobs_changed` events.
- Tightened controlled-send safety. Target prompts preserve perspectives (`ask agent 1 to <do ...>` sends only `<do ...>`), multi-session handoffs stay centrally orchestrated by YO!agent, direct relay/chaining requires explicit user wording, sends use the resolved live tmux pane paste-plus-Return path with Claude/Codex prompt acceptance checks, and jobs re-preview/revalidate before sending. Approval prompts, busy agents, non-agent panes, stale target metadata, missing sessions, and high-risk prompt text do not silently receive bytes.
- High-risk text now forces confirmation even when the user did not ask for preview. Risk labels cover secret-like assignments, credential paths, recursive delete, hard reset, broad `pkill`, recursive permission changes, and SSH commands. Public job/action payloads, persisted YO!agent messages, and event previews redact known `token=`, `secret=`, `password=`, and `api_key=` style values; job idempotency keys are hashes instead of raw JSON signatures.
- Archived the DOIT.67 audit into durable docs: tmux capture remains acceptable for observation, but structured Claude hooks, Codex app-server, ACP/MCP-style APIs, and transcript/event feeds are the durable path for approvals, state, and non-visible agent coordination. Follow-ups for a visible job list, richer recommendation ranking, more watch predicates, structured channels, golden-frame fixtures, and YOLOmux-as-control-plane live in `docs/TODO.md`.
