# DOIT.fs-interactivity.md - Breadth-first Quick Open indexing

## Goal

Make user-configured indexed directories useful immediately: publish each root's direct files at startup, expand deeper directories breadth-first through a fair bounded queue, and refresh paths with concrete change activity in seconds while retaining the 30-minute full scan only as a safety net.

## Context

- [`docs/specs/FS_INTERACTIVITY.md`](../../specs/FS_INTERACTIVITY.md) is the target contract and must be kept in sync with implementation decisions.
- The shipped writer boundary is correct: `yolomux_lib/search/search_indexer.py::PersistentSearchIndexer` owns Quick Open mutations, and web processes read committed snapshots. Reuse `indexd`; do not add another daemon or run tree traversal in an HTTP process.
- Current startup constructs `SearchIndexerClient` but `handle_background_owner_acquired()` starts `jobd` and stats collection without leasing or scheduling `indexd`. `indexd` exits after 60 seconds without clients/leases, so `file_explorer.index_refresh_seconds=1800` is not an independent timer when the daemon is absent.
- Current initial/full work reaches `_walk_root_with_metrics()` through `file_index._run_build()`, which recursively completes a root before publication. Current dirty-directory repair also recursively walks the subtree. A deep or wide descendant can therefore delay shallow search usefulness.
- Cached Quick Open data must remain immediately readable. A cache-hit lookup is not crawling and must not wait behind `jobd`'s single interactive worker or an index queue.
- Existing path authorization, exclusions, symlink/root containment, SQLite single-writer/WAL locality, host partitioning, size limits, tombstones, generation fencing, and stale-snapshot behavior are invariants, not optional cleanup.

## Gotchas

- Do not implement “BFS” by collecting the whole tree with DFS and sorting it by depth afterward; the filesystem open order and first publication time must themselves be breadth-first.
- Do not wait for an entire layer across all roots before publishing one root's completed directory transaction. Layer completion controls the coverage marker, not whether useful rows may become visible.
- Do not delete or blank the old index at refresh start. Cached rows are stale/partial data with metadata, not unavailable data.
- Do not add a second heat map, watcher, scheduler thread, queue, path-exclusion predicate, or SQLite writer. Route existing equivalent paths through one owner and add parity tests in the same change.
- Do not let a broad hot root mean “recrawl the root frequently.” Heat belongs to the smallest canonical indexed directory supported by the evidence, then decays.
- Do not make the 30-minute deadline depend on a browser query, visible Finder, or a daemon that is allowed to exit before the deadline without a wake owner.
- Do not weaken path containment, descriptor authorization, NFS/WAL rejection, exclusions, file/byte/frontier bounds, cancellation, or generation fences to improve latency.
- Keep current results interactive during crawling. A blocked directory, SQLite write, or worker must not occupy the cache-read path or `jobd`'s only interactive capacity.
