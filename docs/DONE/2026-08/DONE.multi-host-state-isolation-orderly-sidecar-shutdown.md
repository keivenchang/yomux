# 2026-08-01 Multi-host state isolation and orderly sidecar shutdown

- Verified and documented the landed multi-host boundary. Chat, login-throttle, stats, pricing, and search now resolve below `hosts/<stable-host-id>/`, where the stable key is `/etc/machine-id` (or explicit `YOLOMUX_HOST_ID`) and the hostname is display-only. Legacy v0.6.10 `events.jsonl` and `stats-v6.sqlite3` remain byte-identical and unlocked; legacy chat database, history journals, and cursor key are preserved rather than migrated or auto-adopted.
- Runtime sockets, leases, and locks now use a host-local, boot-scoped `YOLOMUX_RUNTIME_DIR` root with a socket path within the Unix-socket pathname budget. Filesystem preflight refuses `nfs`, `nfs4`, `cifs`, `smb`, `smbfs`, `9p`, `fuse*`, and unknown filesystem types before WAL databases or Unix sockets are created. Persisted process records are fenced by host, boot, and PID-birth identity before a process can be signalled, reaped, or pruned.
- Shared configuration uses POSIX record locks through `fcntl.lockf`, never `flock`: settings/state use revisioned merge, while auth and YO rules use whole-document compare-and-swap. SIGINT and SIGTERM now run orderly shutdown that stops identity-verified `jobd`, `statsd`, and `statusd` before the server exits.
- Not done: cross-host lock behavior is unverified; the required exporter-local versus NFS-client acceptance remains in [`NFS-LOCK-ACCEPTANCE.md`](../../NFS-LOCK-ACCEPTANCE.md), and do not cite same-host multiprocessing tests as cross-host evidence. SIGKILL remains uncatchable and can orphan sidecars; the deliberately unbuilt surviving-supervisor design is still required for unexpected launcher death. H2/H3 await a user decision because the eleven-subsystem API schema does not exist.
