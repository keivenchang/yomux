# 2026-08-08 The YO!stats Daemons card wall became one service roster

- Replaced the default Daemons grid of bordered Server, CPU budget, Distributed owner, Worker totals, Search & caches, Events & chat and Tmux signal watcher boxes with one compact summary strip, one compact alert slot, one full-width service roster, and one collapsed Advanced diagnostics section. The roster shows every daemon with status, average/maximum latency, uptime, memory, CPU, restarts, requests and errors on one line; the YOLOmux web process is its first row and the tmux signal watcher is that row's child. No second endpoint, poller, observer, latency owner, service inventory or status classifier was added: row order comes from `local_service_projection.LOCAL_SERVICE_INVENTORY`, labels from `app.system_status_service`, paint from one `debugSystemStateTone`, and every cell from the one existing `debugSystemMetricText` envelope renderer.
- Fixed the refresh path first, because everything else depended on it. `refreshDebugSystemViews()` used to run `view.innerHTML = debugSystemInnerHtml()` twice per 5s poll, destroying the whole Daemons view; nothing was focusable, so nobody noticed. It now replaces only the regions whose HTML changed and restores focus by a stable key, so an open row keeps its DOM node, its focus and the panel's scroll across a poll. `tests/test_gate_panels.py::test_roster_refresh_preserves_expansion_focus_and_scroll` pins all three, and reverting to the whole-view rebuild turns it red.
- Per-service diagnostics are now BUILT lazily instead of rendered and hidden. The always-on detail row under every service -- six transition lists, six coverage blocks, the sampler families table and the cache/queue dictionaries -- is gone from the default DOM and constructed only for an expanded row. Each row has one real `<button>` disclosure with `aria-expanded` and `aria-controls`, so mouse, Enter and Space reach the same one handler.
- Unmeasured values render `—` with their reason in the row title, their code in `data-metric-reason`, and their full sentence in the disclosure -- never `0`. The web process's Restarts/Requests/Errors/Latency are structurally unobserved and say so with reason code `web_process_not_observed`; the tmux watcher's process metrics say `subsystem_not_observed`. No schema-2 extension and no fresh measurement inside `system_status_service` was added to manufacture them.
- Localization: 26 new keys across all 19 catalogs, with eight concepts routed to the existing owner key instead of a synonym (`debug.tab.services`, `state.idle`, `debug.graph.chart.cpu`, `backgroundOwner.thisServer`, and four `debug.system.localServices.field.*`), which is what `tools/static_build.py`'s duplicate-concept and untranslated-value checks require.
- Verification on one frozen candidate: `node tests/system_health_panel.test.js` 28 passed / 0 failed, `node tests/layout_url.test.js` 18 shards passed, `python3 -m pytest -q tests/test_gate_panels.py` 10 passed / 4 xfailed, `python3 tools/static_build.py` and `--check` both exit 0. Eight negative controls were watched failing first: whole-view rebuild, rebuild plus no focus restore, eager detail rendering, an unrendered disclosure target, the web row's four columns as zeroes, rows re-sorted by health, the card grid restored to the default view, the responsive container query removed, and the child row stripped of its parent.
- `python3 tools/check.py` exits 1 on this candidate, and every remaining failure was A/B-verified against this branch's base commit rather than assumed: the stale `textshape_assertion_guard` inventory hash (this branch's test files contribute 0 of the 362 candidates), `test_auto_approve_lock` (2), `test_local_services_launch` approvald SIGTERM, `test_gate_budgets` L4/L6 approvald, `test_e2e_auto_approve` (4), `test_browser_finder` 64-item batch, and the `test_gate_api_errors`/`test_gate_launch` journey errors all fail identically at the base commit. `test_gate_tmux` D7 is a latency budget that fails inside the isolated container and passes on the host at BOTH revisions. `test_browser_finder::test_sync_finder_follows_clicked_editor_file_to_repo` and `test_gate_interaction` I3 appear only under the parallel check's load and pass serially. Four failures the redesign really did cause were found by that check and fixed here: a `:7771` literal the test-isolation rule forbids, the two `test_browser_layout` System assertions that pinned the retired card grid and the sampler's default-DOM position, and the `test_e2e_system_status` recovery banner's 80px minimum height.
