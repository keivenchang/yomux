# Development

Go is the target and default server for managed/operator launches, including `boot.sh`, `make run`, and `yolo-dev-start`. The Python server is a deprecated temporary fallback. All supported Python-only product behavior must move to Go before Python removal; the Go HTML renderer, runtime dependencies, contributor/build tooling, and companion tools are also part of that removal work. Product validation targets Go. This page keeps the commands contributors need; code-level ownership rules live in `AGENTS.md`.

## Setup and checks

Install the Python runtime and development dependencies with `make dev`. Python 3.11 or newer is required. Runtime dependencies, including `watchfiles>=1.2.0`, and the `dev` extra (`mypy`, `pillow`, `pytest`, `pytest-timeout`, `pytest-xdist`, and `selenium`) are declared in `pyproject.toml`. `.bazelversion` owns the Bazel version; `MODULE.bazel` owns the Go SDK and Bazel rules, with a source check keeping the `go.mod` rules_go mirror aligned for Go runfiles imports. Docker is required for the certified isolated Go test lane; the runner also supports warned native execution on machines without Docker. Image preparation resolves and verifies the pinned offline dependency inputs before tests run without network access.

Run the canonical gate before landing a change:

```bash
python3 tools/check.py
```

The runner lists available lanes with `python3 tools/check.py --list-lanes` and runs independent lanes in parallel by default. For focused work, use `python3 tools/check.py --lane <name>`. The `bazel-go` lane owns the complete Go suite; do not run the full gate and the Go wrapper back-to-back on the same tree. `auto` uses Docker when the daemon is available. Image preparation or admission failure stops the run with a prominent warning; there is no automatic native fallback. Pass `--execution native` for separate non-hermetic diagnostics. Native mode uses host binaries found on `PATH`, and skips its Chrome E2E target when Chrome/Chromium or ChromeDriver is unavailable. On macOS it also selects the macOS Go SDK. Linux budgets pytest workers and Bazel jobs against 100% of schedulable capacity by default; `--cpu-percent` and `YOMUX_CHECK_CPU_PERCENT` can lower that budget. Browser and E2E workers each reserve two CPUs for Chromium and their fixture server. Pytest containers keep their memory limits and worker counts but have no hard CPU quota, so they can use capacity released by lanes that finish early or reuse cached results; the Bazel container retains its configured CPU limit. For example, 32 logical but 24 schedulable Linux CPUs produce 6/4/2 pytest workers and 6 Bazel jobs.

Go YO!stats supports host CPU, memory, and mounted-filesystem usage, process CPU and RSS, agent inventory, and daemon-process CPU and RSS on Linux and macOS. macOS collection uses Mach host counters and libproc process data; other operating systems report those measurements unavailable. New samples are collected at the existing product cadence, so older persisted gaps remain unavailable.

The default gate is development validation, not latency certification. Use `python3 tools/check.py --certify` for the explicit certification run or `python3 tools/check.py --certification-only` when certification is the only requested lane; a normal green gate reports `NOT CERTIFIED`.

The six current strict xfails are temporary sentinels for deferred session recovery, owned by `queues/backlog/DOIT.p2.e5.recovery-preflight-identity.md`; they do not establish reproduced application defects. Unconditional reminders for other contracts were retired in favor of concrete coverage follow-up in `queues/backlog/DOIT.p2.e3.go-supported-contract-coverage.md`. The old SubsystemSpec controls and three-card Daemons expectations are outside the current Go scope; the current roster tests own the supported presentation. Cross-host snapshots remain unsupported as documented in README.md.

Default checks (`python3 tools/check.py` and bare `python3 -m pytest`) test Go, the frontend, and required tooling. Python-written tests that drive Go remain enabled. Legacy Python backend unit, indexing, search, status, HTTP, and coexistence tests carry `deprecated_python_server` and are disabled by default. Wholly deprecated modules are excluded before import; deprecated cases in mixed modules are deselected before fixture setup. They remain only for explicit maintenance until the Python backend is removed. Use `python3 tools/check.py --run-deprecated-python` to admit them alongside the normal checks, or `python3 -m pytest --run-deprecated-python -m deprecated_python_server` to select only legacy Python cases. `-m deprecated_python_server` alone does not enable them. Both options survive Docker delegation. Go-side Python comparison and downgrade contracts also require the maintenance option; direct Bazel maintenance uses `tools/run_bazel_tests.sh -- --test_env=YOMUX_RUN_DEPRECATED_PYTHON=1`. Newly added tests must declare a backend role when they reference legacy implementation helpers; `shared_tooling` is for fixture and process safety, and `go_backend` is for actual Go drivers with Python fixture builders.

Use `python3 -m pytest <path-or-test>` for a focused test. `node tests/layout_url.test.js` runs the focused Node/browser-source shards. Automated browser and Go tests use fixture-owned state and ports; they never use the operator server on port 7220.

Frontend source lives in `static_src/`. `static/yomux.js` and `static/yomux.css` are ignored build outputs and are not tracked by Git. `make setup`, `make dev`, and `tools/check.py` generate them when missing or stale; after frontend source changes, run `python3 tools/static_build.py`. Use `python3 tools/static_build.py --check` to verify the generated files without writing them. The old `/static/yolomux.js` and `/static/yolomux.css` URLs resolve to the same bundles during the transition. Focused browser and Node tests need the generated bundles; run `make dev` or the builder first on a fresh checkout.

Build Go with the platform-selected SDK:

```bash
tools/build_go.sh
```

The build and test wrappers use the same SDK selection: Go 1.27.1 on Linux and macOS, where its Mach-O UUIDs are required by local-network binaries. Bazel 9.2.0 is pinned in `.bazelversion`; `MODULE.bazel` owns the SDK, rules_go, Gazelle, rules_shell, and platforms versions. Run `python3 tools/check.py --lane bazel-go` for the complete Go suite. `tools/run_bazel_tests.sh` runs that lane directly and accepts `--jobs N`, `--memory-mb N`, `--target LABEL`, `--execution auto|native|qualified-native|docker`, `--cache=on|off`, `--reuse-test-results`, `--rerun-tests`, and trailing Bazel arguments after `--`. Docker mode uses Bazel’s hermetic Linux sandbox inside a network-disabled, non-root test container and reuses passing test results by default. `--rerun-tests` forces test execution; `--cache=off` disables the shared disk action cache and also forces test execution. `--reuse-test-results` remains accepted for compatibility and conflicts with `--rerun-tests`; test freshness options do not change action keys. Docker test cache identity includes the exact image ID, Linux kernel/platform, pinned seccomp and AppArmor policies, and sandbox configuration. Each test gets private HOME, temporary files, PTY devices, PID/network namespaces, and Bazel-declared runfiles; checkout Git metadata and undeclared checkout files are unavailable inside the test sandbox. Docker admission rechecks the image, mounts, credentials, network, and Linux sandbox before every invocation, including cache hits. On Linux, `auto` requires Docker and stops if the daemon is unreachable or cannot satisfy isolation; host diagnostics require a separate explicit `--execution native` invocation. On macOS, `auto` retains native execution. Native diagnostics never establish canonical Docker acceptance. `--execution docker` fails admission instead of falling back. Native mode uses the machine’s existing `PATH` for tmux, Git, Python, browser tools, agent clients, and other test executables; those binaries and host state are not pinned, so native results remain outside the Docker hermeticity guarantee and test-result reuse stays opt-in. Bazel itself must match `.bazelversion`, and Go uses the SDK selected by `MODULE.bazel`. Native `--memory-mb` sets Bazel scheduling capacity with `--local_resources`; it does not impose a process memory limit. Docker applies a hard container memory limit. Native invocations use private writable execution state by default and use a user-owned mode-0700 persistent output root only when test-result reuse is explicitly enabled with `--cache=on`; compiled actions use the user-owned disk cache. Trailing Bazel arguments may select tests and test filters; options that weaken the execution contract are rejected.

On AppArmor-enabled Linux hosts, install the dedicated policy once with `python3 tools/bazel_execution_contract.py --install-apparmor`. This explicit setup uses non-interactive sudo; regular tests only validate the policy. The validator compares the freshly compiled source with the kernel-exported policy digest and requires enforce mode. A missing or changed policy refuses admission. The profile preserves Docker's filesystem restrictions and permits the nested namespace mounts and pivot-root operation required by Bazel; outer capabilities remain dropped. Profile installation is host-local and must be repeated after reboot or policy source changes.

The required registry pin and buildifier module graph are tracked source inputs. Image preparation checks them before downloads and uses private module inputs. Network access is allowed during preparation; test execution remains offline. Gate reports carry structured execution records, including admission failures and native target omissions. `YOMUX_CHECK_CONTAINER=0` controls host orchestration; it does not select native Bazel execution.

## Mac Repo Diff cache qualification

The macOS Git adapter uses one service-owned immutable-tree cache for objects and loose refs. Each request keeps HEAD, index, packed refs, shallow metadata, and sanitized config private. The cache checks descriptor identity and complete inventory stamps, including ctime, before reuse; it holds leases until namespace closure and coalesces builds for the same inventory. A warm history-result cache must not rebuild the object or refs snapshots. Cache capacity covers both tree types across multiple repositories, and reused entries still count against the namespace limits.

Do not remove, bypass, make request-local, or replace this cache or its reuse assertions unless the replacement is confirmed on a real Mac. This requirement applies to human and AI editors, including refactors of Git history, stats, Differ, service construction, fingerprinting, clone options, or namespace cleanup. A Linux gate does not run Darwin tests. A reused return path alone does not prove absence of duplicate cloning; HEAD-only or TTL-only cache keys do not detect ref moves, object mutations, or namespace replacement.

Run `tools/run_bazel_tests.sh --target //internal/finder:finder_test -- --test_filter=TestDarwin --test_output=all` and the same command with `finder_race_test` on macOS. Require zero new cached-tree builds during repeated actual history loads, one clone builder for concurrent identical acquisitions, prompt waiter cancellation, correct cold/warm entry budgets, and intact leased generations after mutation. Preserve coverage for same-size writes with restored mtime, source symlinks, loose-ref updates, packed-ref transitions, absent refs, linked worktrees, and source swap-and-restore while Git executes. Do not weaken these assertions to make a refactor pass.

Then build and restart the active development server using the commands below. Repeat authenticated requests for the actual repository: `/api/fs/git-history?path=<repo>&limit=50&worktree=0`, `worktree=only`, and the visible history statistics stream. Record the first request and at least three warm requests, response status, commit count, and the rendered Repo Diff history in real Chromium. Compare the same workload before and after the change; do not claim Mac performance from a synthetic response or a Linux measurement. On 2026-10-14, yo8880 history took 7.17 seconds on the first probe and 1.53-1.80 seconds on repeats; direct Git history took 22 ms. The live Go profile identified repeated object-file opens and uncached loose-ref cloning. The object cache introduced in v0.10.2 was still present; loose refs had never used it.

Mac qualification on base `e8e1e824590962ee5e333ed782877762c2007bc0`: 26 Darwin tests passed with the race detector, and an isolated negative control that removed concurrent-build coalescing failed with two clone builders. The restarted yo8880 server returned 50 history commits with HTTP 200 in 0.838, 0.664, and 0.664 seconds on three warm requests; working-tree status took 0.607 seconds. Real Chromium rendered 31 history rows and 38 enriched commit counts without history/stats errors, and the served JavaScript hash matched the rebuilt bundle. The first cold browser load still took 6.136 seconds; this cache is service-owned and does not survive restart. The broader native Finder target reported 230 passing and 33 failing top-level tests; all 33 search-index/discovery failures also reproduced on unchanged prior base `4d33cbc967ef13772f1339f58189816a70952c9e`. These focused Mac results do not establish a green full gate or release readiness.

### Qualified native gate

Use `--execution qualified-native` to run the parallel functional gate without Docker. Prepare the platform bundle before starting the gate; execution refuses missing dependencies and never downloads them. Use secondary scratch storage when available and `/tmp` otherwise. The bundle must be outside operator HOME on macOS.

The acquisition command copies platform tools and prepares the locked Python packages, agent clients, Go modules, Bazel registry, and repository cache. macOS acquisition requires arm64 and matching installed Python, Node, Go, Bazel, JDK, Command Line Tools, and cached Chrome/ChromeDriver. Linux acquisition exports an existing immutable comparison image; Docker is used during that preparation only. A host without Docker can receive the prepared platform bundle or freeze an already prepared runtime layout with `tools/native_bundle_prepare.py --layout <layout> --output <bundle-directory>`.

```bash
# macOS dependency preparation; network access is allowed here.
python3 tools/native_bundle_acquire.py --output /tmp/yomux-native-bundle

# Linux dependency preparation; supply the comparison image's full sha256 ID.
python3 tools/native_bundle_acquire.py --output /tmp/yomux-native-bundle --linux-image "$YOMUX_COMPARISON_IMAGE"

# Offline execution, after preparation has published both manifest locks.
export YOMUX_NATIVE_BUNDLE=/tmp/yomux-native-bundle/payload
python3 tools/check.py --execution qualified-native
tools/run_bazel_tests.sh --execution qualified-native

# Focused pytest delegates through the same qualified Bazel runner.
YOMUX_BAZEL_EXECUTION=qualified-native python3 -m pytest tests/test_native_bundle_contract.py
```

The bundle manifest locks file bytes, modes, links, executable paths, and Python package versions. One gate session verifies that inventory, captures the source and Git context, and admits tools, offline Go dependencies, and the complete dependency graph before starting result-bearing tests. Each lane reuses one private execution worker and Bazel server across its steps, with a fresh uncached sandbox probe before cached results are allowed. Output leases remain held through process retirement; failed retirement quarantines the output slot. Final acceptance requires worker cleanup and complete bundle reverification. Required browsers and agent clients cannot be omitted. Linux requires the dedicated AppArmor policy, hermetic `linux-sandbox`, private devpts, namespaces, and dropped capabilities. Its runtime filesystem comes from the bundle. Each Linux entrypoint owns a private child subreaper so detached descendants cannot escape cleanup by replacing their environment.

macOS uses stock Bazel with processwrapper staging and timeout handling. The existing test entrypoint allocates its private fixture, then applies one Seatbelt policy to the test command and all descendants. The policy denies external networking, operator-home reads and writes, launchd job creation, LaunchServices app launches, Apple Events, and writes outside fixture state, action temporary state, declared outputs, and required devices. Setup, repository rules, and non-test build actions run without OS sandbox enforcement. Execution records identify this boundary as `test-process-tree`, with `setup_os_sandboxed=false` and `non_test_actions_os_sandboxed=false`; final coverage requires matching scope and platform evidence. Undeclared host reads outside blocked paths, host localhost access, and host process visibility remain measured Mac limitations. Existing services reachable through localhost or Unix sockets run outside the test policy and can broker work outside the test process tree. The allocation journal and launchd resource coalition supervisor run outside the test sandbox; owned descendants must retire before output slots or fixture directories are released. Failed retirement preserves quarantined invocation state. Admission requires a fresh real Bazel sandbox probe before cached test results can qualify, and execution identity includes the policy and its scope.

`BUILD.bazel` owns the executable coverage inventory, including the complete Go suite and the Python, Node, static, and integration steps. Git revision and dirty-state checks stay in orchestration. The qualified runner keeps the existing lane and worker parallelism. Structured execution records report coverage completeness and individual measured isolation guarantees. Result identities include the bundle, platform, SDK, and execution policy; Docker and qualified native results use separate caches. Latency certification remains a separate Docker workflow.

## Go credential and storage admission

Go stores password-admission state in `YOMUX_STATE_DIR/go-login-rate.sqlite3` (config directory fallback when state is unset), separate from YO!stats. `go-login-rate-secret` supplies HMAC identifiers. Admission uses atomic SQLite transactions across processes selecting the same state root, with at most 32 in-flight verifications, two-minute abandoned-claim expiry, and a 50,000-row bound. Expiry does not refund network charges. Unknown usernames, including unknown hard locks, expire after six idle hours without an active claim. Configured-account hard locks persist; other usernames expire after six idle hours once their cooldown and claims end. Policy overrides load from the selected config directory's `login-rate-limit.json` at first credential use; restart after changing them. Invalid overrides retain the documented defaults. Cookie and limiter secrets share complete, non-replacing secret publication.

The Go config/journal lease is `go-storage.lock` in the canonical config directory. Keep it until process exit so final HTTP, collector, and health writes cannot race a replacement process; do not unlink a held lock. Config journal paths remain unchanged. Auth and stats storage must pass the shared Linux/macOS local-filesystem probe before mutable admission. Unknown or failed probes refuse admission. `YOMUX_ALLOW_NETWORK_FILESYSTEM_MUTABLE_ROOTS=1` is the existing warning-producing emergency override, not supported network WAL operation. Source checkouts may still reside on NFS when mutable roots are local.

The isolated stats crash/restart qualification uses `python3 tools/verify_go_stats_restart.py --binary <built-Go-binary> --output /tmp/yomux-stats-restart.json`. It owns private client roots, tmux, config/state, databases, and reserved ephemeral listeners. It runs a 64-file approximately 64 MiB cold backlog with 180 one-second live appends, kills only its fixture Go process at 90 seconds, reconnects authenticated SSE, and checks exact tokens, deduplication, checkpoints, and coarse-product convergence. Newly selected coarse products request a fresh open-bucket fold; repeated polling retains the background cadence. This workload is a fixture qualification, not a production-scale benchmark.

Finder index schema 2 migrates supported Go records into a private candidate, validates records and relationships, checkpoints the original, and retains a uniquely named same-filesystem rollback link before atomic publication. Publication phases are recorded next to the database. Interrupted candidates and rollback databases are retained for inspection; do not remove them as part of normal restart or persistence changes. Newer schemas are rejected by a read-only header/WAL probe before SQLite can create sidecars. Refresh candidates use measured allocation and bounded checkpoints; failed candidates count toward later transient admission. Reclamation removes only unused directory leaves and runs in bounded SQLite batches.

## Local servers

New operational configuration uses `YOMUX_*`. Legacy `YOLOMUX_*` inputs remain accepted and produce a deprecation warning that lists no values. When both names are present, the canonical value wins, including an explicitly empty value; empty keeps the setting's existing default behavior. The shared shell adapter is maintained in `tools/product_environment.sh`; installed launcher copies must match it. Compatibility aliases carry fingerprints so repeated normalization and child processes can distinguish generated aliases from new legacy input.

The Linux workspace uses `~/dev/yomux`, with the inner `yolomux.repo` basename and existing worktree names preserved. A temporary `~/dev/yolomux` compatibility link keeps active agents and saved paths usable. Review that link 30 days after both hosts pass acceptance; retire legacy environment input separately when supported callers no longer need it. Application data, credentials, TLS files, caches, sockets, and lock destinations retain their configured paths.

After a change, restart the active development server before reporting it ready. `./boot.sh <port>` starts Go by default after the Bazel binary is built. The `yomux-dev-start` workflow also starts Go explicitly for configured numbered checkouts. Use `./boot.sh --deprecated-python <port>` or `python3 yomux.py --backend python` only when validating the deprecated Python fallback. Direct `python3 yomux.py` starts Go by default.
To keep an existing HTTPS identity during a backend cutover, pass `./boot.sh --force --no-dev --port <port> --cert <certificate.pem> --key <private-key.pem>`. Both readable files are required before the launcher touches logs or listeners. Direct launches honor explicit `YOMUX_CONFIG_DIR`, `YOMUX_STATE_DIR`, `YOMUX_CACHE_DIR`, and `YOMUX_START_LOCK_DIR` values; use the same roots for authenticated probes.

Managed startup does not gate or wait on CPU usage, memory usage, or OS load averages. The legacy `--ignore-load` option and `YOMUX_START_LOAD_WAIT_SECONDS` setting are accepted only for compatibility and do not affect startup. Root validation, instance ownership, startup locking, and listener readiness checks remain enforced.

On macOS, managed servers use per-port sessions on the default tmux server. The launcher clears inherited tmux socket settings before applying its explicit launch environment.

Port 7220 is the operator runtime. Port 7221 is reserved for a manual Go preview. Automated tests must use fixture-owned ports. Restart production only when explicitly requested.

Verify the selected listener and health endpoint after restart. For Go, check `/healthz`, `/api/capabilities`, the process checkout, and the exact browser path affected by the change. A source test does not prove which bundle a running server serves. For activity-driven Tabber reordering, reproduce in Chromium with the pointer held over a row and changed recency; assert unchanged row geometry, continued status/date updates, and the same native click target in Normal and Advanced. Cover pane whitespace, active popovers, immediate reentry, new/exited sessions, explicit sort, and disposal. Verify relative defaults, saved Date/None and URL migration, and later choices across reloads. Rebuild assets, then repeat the authenticated hover/exit journey on the explicitly selected restarted port and verify its served bundle matches the build.

NFS-mounted source checkouts are allowed, but tests, browser profiles, sockets, caches, logs, and evidence must use host-local temporary storage. Do not point two hosts at one mutable runtime or database root.

## Landing changes

Local `cps` rebases onto local `main` and fast-forwards the integration checkout; it does not bump a version or push. `cps origin` rebases onto `origin/main`, includes the version bump in the work commit, fast-forwards local `main`, then pushes after the merge succeeds. Both modes require the canonical gate first. Stage explicit files only; never use `git add -A` for a release.

`version.yaml` is the product-version authority. A release version bump increases its quoted `major.minor.patch` value; the Go build generates an immutable version constant from this manifest, and Python package metadata reads the same manifest through its compatibility module. `.bazelversion`, the Go SDK, and `go.mod` are toolchain pins. The check runner validates the manifest, generated Go version, and release commit/tag. A global release commit subject must be `Release YOmux <version>`, its annotated tag must be named `v<version>` with tag message `YOmux <version>`, and the tag must point to that release commit; create the tag only after that commit passes the gate, then push `main` and the tag atomically.

Go checks `origin/main` at startup and hourly unless `updates.notify_level` is `none`. It reads `version.yaml` from the fetched commit and applies the configured major/minor/patch threshold. `/api/update-status` returns the cached result, check time, and error; browsers query it on startup so they do not need to receive the original event. The admin Update & restart action prepares the pinned Go binary and static bundle before a fast-forward and launches the selected port through `boot.sh`. It refuses dirty or diverged checkouts. Job progress is available at `/api/self-update/status`; completion requires a new instance reporting the target version.

`cps` does not restart servers. Restart and verify the active development server separately. Production restart requires an explicit request.
