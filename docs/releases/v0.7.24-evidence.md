# v0.7.24

Landing record for annotated release `v0.7.24`. The release moves bounded filesystem and Git reads out of the jobd request queue so interactive reads can complete directly on the accepting server.

## Changes Since v0.7.24

The following two changes are committed after the `v0.7.24` tag, followed by additional uncommitted Quick Open work in the current development checkout. They are listed here for the requested comparison, not presented as contents of the immutable `v0.7.24` tag.

### Committed After The Tag

- **Interactive filesystem reads are separated from deferred batch work.** Direct Finder listings, index-status reads, path metadata without Git enrichment, terminal file-candidate probes, and initial file reads stay on the accepting web process. Recursive search, cursor-based search deltas, ZIP/count/HTML preview work, blame, and other input-sized operations use the deferred filesystem batch path. This keeps small interactive reads from waiting behind CPU-heavy work while preserving bounded receipts and completion ownership for deferred operations.
- **The deferred work service is renamed from `jobd` to `batchd`.** The service module, infrastructure owner, client, routes, status projections, tests, gate helpers, and documentation now use `batchd` consistently. The rename includes scheduler and worker terminology, local-service lifecycle and retirement paths, route names for deferred filesystem work, and the associated test files.
- **Batch admission and lifecycle behavior was tightened.** The batch broker validates task payloads, priority, generation, deadlines, and coalescing keys; rejects work during shutdown or when a lane is full; preserves accepted-work completion ownership; reports typed admission rejection; and keeps status, product, worker, queue, and scheduler-failure information bounded. The broker protocol compatibility pin moved with the rename.

### Additional Current-Checkout Work

- **Quick Open now has separate path and indexed-search modes.** Absolute and `~` queries use one authorized, non-recursive parent-directory listing through `/api/fs/fast/list`, then filter the cached names locally. Ordinary queries use configured indexed roots through `/api/fs/search-stream`, with the compatibility search route retained for non-stream callers.
- **Quick Open search results are streamed and ranked.** Indexed results arrive in bounded chunks, are fenced to the producing root, reject weak matches assembled from unrelated path fragments, and prioritize open tabs, the newest 100 opened file paths held in browser memory, the active Claude or Codex working directory, and then remaining indexed results.
- **Quick Open retains useful state during loading.** Rows from the previous query remain visible while a replacement request is pending but are marked stale and cannot be selected. Stale requests and late stream chunks are fenced so they cannot overwrite the current query. Parent-directory listings are reused until filesystem invalidation requires a reload.
- **Quick Open can render up to 500 rows.** The frontend display cap now uses the shared `fileQuickOpenResultLimit` value, which is 500 and matches the request limit. The result pane remains scrollable through those rendered rows; the backend hard maximum remains 2,000.
- **Regression coverage expanded.** Tests cover direct name-only search, non-recursive directory results, indexed stream framing and disconnects, stale request fencing, cache reuse and invalidation, ranking tiers, the 100-entry history cap, indexed basename admission, and the 500-row display limit.

These post-tag changes are not a release tag or release commit yet. The current checkout also contains unrelated pre-existing worktree changes and deletions; those are not included in this list.

## Shipped scope

- Finder directory listing, index-status reads, path metadata without Git enrichment, and terminal file-candidate probes execute directly instead of waiting for jobd.
- Git history, Git commit detail, and file Diff execute through a bounded direct Git owner instead of jobd.
- Direct Git history includes file totals and colored additions/deletions, while historical file tabs select immediately and load comparison bytes in the background.
- The direct Git scope preserves descriptor-based authorization, repository-generation checks, alternate-object rejection, packed-object checks, bounded output, and typed failures.
- `STATUS-REPORT.md` is no longer tracked. Active `queues/backlog/DOIT*.md` files remain local coordination files and are not release inputs.
