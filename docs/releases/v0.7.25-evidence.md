# v0.7.25

Landing record for the global release containing the complete post-`v0.7.24` worktree change set. The exact tested subject SHA and final annotated tag target are recorded after the release commit and tag are created.

## Shipped scope

- Interactive filesystem reads are separated from deferred batch work. Small Finder listings, index-status reads, path metadata, terminal file-candidate probes, and initial file reads execute directly on the accepting web process; recursive or input-sized search, archive, count, preview, blame, and batch work use the deferred path.
- The deferred work service is renamed from `jobd` to `batchd` across service modules, sockets, clients, lifecycle handling, routes, status projections, tests, gate helpers, and documentation. Bounded queues, coalescing, cancellation, receipts, worker replacement, and typed admission failures remain part of the service contract.
- Quick Open separates empty, path, and indexed-search behavior. Empty Cmd-P shows recent opened files locally without a request and includes each file's last-opened date/time. Absolute and `~` paths use cached non-recursive direct-directory lookup. Non-absolute queries use streamed indexed search through `/api/fs/search-stream`.
- Quick Open indexed results arrive in bounded chunks, preserve scroll position, reject rows outside their producing root, prioritize useful basename and path-segment matches, and rank open tabs, the newest 100 browser-memory file paths, the active Claude or Codex working directory, and remaining indexed matches in that order.
- Quick Open retains up to 100 opened file paths in browser memory and renders up to 500 result rows. Stale rows remain visible during replacement requests but cannot be selected, and late responses cannot overwrite a newer query.
- Search indexes support lightweight metadata-free reads and SQL ordering for exact basename, basename-prefix, and basename-fragment matches. Direct path search matches names before opening child metadata.
- The generated JavaScript bundle, architecture budget fixture, backend tests, browser helpers, Node tests, and route/search tests were updated with the implementation.
- The three completed `docs/DONE/` records removed in this worktree are included in the full global change set.

## Verification

- Focused Node layout, editor/preview, static-build, generated-bundle, syntax, Python compilation, whitespace, and diff checks passed before release preparation.
- The canonical `python3 tools/check.py` run was attempted on the dirty release candidate. Static, Node syntax, Node layout, Python compilation, whitespace, and the serial lane passed. The browser lane reported three existing boot/mobile failures, and the end-to-end lane reported a batchd result timeout plus a fixture teardown error. Exact-SHA certification was not certifiable because the candidate was dirty and the host preflight exceeded its CPU-stall limit.
- The release record does not claim the failed browser or end-to-end checks as passing. Their raw command output remains under the local tool-output and `/tmp` evidence paths rather than in the repository.
