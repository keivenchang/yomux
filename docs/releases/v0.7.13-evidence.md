# v0.7.13

Landing record for annotated release `v0.7.13`. The final release commit is the object resolved by `v0.7.13^{commit}`; the exact pushed SHA is recorded in the release handoff after the tag and origin refs are verified.

## Shipped scope

- File watching no longer reports a starting or idle watchd as an errored daemon. `v0.7.12` already classified one watchd startup case as `starting`; this release closes the remaining windows in which the bridge had no branch for the daemon's own report and fell through to `errored`. A watchd with nothing registered to watch is now typed `idle`, and a watchd whose current watch generation has not been activated yet is typed `starting`. Both are handled exactly like `polling`: the service row reports healthy while `filesystem_healthy` stays false, so no consumer begins trusting a watch mirror that is not live. A failed initial scan is separately published against the exact failed generation and takes precedence over `starting`, so a real scan failure remains yellow and exposes the typed `watch_generation_scan_failed` reason without publishing a co-tenant path from the daemon error.
- Because the false `errored` was a legitimate degraded contribution to the shared aggregate, the top System triangle no longer turns yellow for it. No aggregate, tone, or topbar code changed in this release; the yellow simply no longer has a false source.
- Focused YO!stats graph controls no longer defer an accepted history generation until focus leaves the control. Range, resolution, visibility, and zoom-reset interactions preserve focus while repainting the chart body immediately, so the control state, plotted range, and accepted data generation converge in one user-visible transition.
- YO!stats graph gestures now release every repaint they defer. A drag-zoom can paint its new shell before the requested history arrives; if that arrival was deferred by the next live gesture, several interaction exits could clear their owner without releasing the repaint, leaving every chart body blank with no live ticker on the fixed zoom domain. Pointer-up now flushes after either zoom branch, touch-scroll and candidate cancellation flush when they retire the candidate, and range-slider change, pointer-up, and pointer-cancel share one drag-end flush.
- Persisted YO!stats ring reads now keep a cursor per resolution, derived from the newest physical slot at that resolution instead of a process-wide publication generation. The last accepted cursor is also retained as a freshness floor after a contradicted persisted view is discarded. Together these changes prevent a delayed publication at one resolution, or a stale source-0 startup cache entry, from replacing newer data with an incomplete zero bucket.
- A direct Codex transcript now returns to the scanner's live-priority tier when it grows after a bounded scan stopped partway through the file. Previously, a transcript without a committed EOF became historical after partial consumption, so newly appended token and cost events could wait behind legacy repair backlog. Live growth can consume at most two consecutive committed scans before one historical source leads the next scan, and a separate commit-only historical cursor rotates that bounded turn across repair and backlog sources. This keeps current token and cost updates prompt without allowing continuous growth to starve older transcript repair.
- Finder and Differ session-files requests now retain ownership of their own finite HTTP transports. A peer destination may reuse a completed payload only while idle; a pushed or terminal payload fences an older response through the existing generation guard without aborting an otherwise successful request into a client-side status 0. This removes completion-order-dependent failures and stale payload replacement.
- Session-roster membership changes now pass through one adoption owner for statusd snapshots, direct tmux refreshes, creates, renames, and kills. That owner feeds the existing transcript-metadata rebuild and publication pipeline, so a newly accepted 14-session status roster cannot remain paired with metadata for only 12 sessions. The status-service app adopts the roster but does not start a browser transcript-metadata publisher; normal web mode remains the single publication owner.
- Housekeeping already on `origin/main` at branch time: the abandoned v0.7.12 queue closeout.

## What this release does NOT claim

- No claim that this release changes statsd daemon-health timeouts. The periodic `probe_timeout` reported against YO!stats did not reproduce on `v0.7.12`, and every retained occurrence predates that server start. The YO!stats changes in this release correct graph paint and persisted-ring data ownership, not the health-probe path.
- No traversal change. The suspected depth-first traversal starvation in watchd was measured against the shipped code and refuted: every native registration is `recursive=False`, there is no `os.walk` or `rglob` on that path, and directory signatures are bounded by `WATCHD_SIGNATURE_CHILD_LIMIT`. No breadth-first rewrite was made or needed.

- The first loaded run failed `test_browser_ring_landing_verify::test_ring_landing_real_page_restart_and_zero_gap`: a seeded cost of 12 rendered as 0. That was a release correctness defect, not dismissed as load; the focused graph and resolution-local ring fixes above address it and retain the exact browser regression.
- Other loaded-run failures were classified outside the release's product diff: `test_check_runner::test_pytest_timeout_fails_loudly_with_faulthandler_stack` and `test_check_runner::test_default_check_gate_exits_not_certifiable_when_the_host_is_unqualified` exercised host-tooling behavior; the static lane's `check_local_service_types.py` found that the declared `mypy` tool was absent from this Python environment, after which the declared dependency was installed for the exact user Python and the gate passed; `test_gate_tmux::test_gate_d7_kill_session_api_returns_promptly_and_removes_scoped_session` received an HTTP 500 from the tmux test environment; and `test_gate_api_errors::test_authenticated_normal_session_journey_has_no_unowned_non_2xx` reproduced passing in isolation after a parallel-load failure and passed twice on the consolidated tree.
- Two gate failures during this work WERE in this release's diff and were fixed before release: an architecture-budget growth and an import placed inside a test function. The architecture manifest was then updated deliberately across 16 reviewed scalar entries: 14 upward ratchets and two downward tightenings.
- Canonical-1 still exited 1 despite all 7 exact-SHA host and latency certification units passing. The amended single-commit tree needs a fresh canonical `python3 tools/check.py` run; until that functional gate and its exclusive certification phase pass on the exact amended SHA, this candidate is neither release-certified nor published.
- The live acceptance window is 32 minutes of retained history and 20 minutes of sampling, not an overnight soak, and watchd spawned a small number of times within it rather than dozens.
- **Carried forward from v0.7.12, unchanged:** while the Daemons panel is visible, a pushed `backend_health_changed` revision updates the System triangle immediately but the rows refresh only on the next five-second `/api/system-status` poll, so the two can disagree until a later poll.
