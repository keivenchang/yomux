# v0.7.1 release evidence

This page records what actually shipped as `v0.7.1`. Unlike [`v0.7.0-evidence.md`](v0.7.0-evidence.md) — which audits a *different, rejected* candidate (`b8e0f61de`, "acceptance bar recovered; candidate not accepted") and is not evidence for this release — this page documents an accepted, tagged, and live release and the closure it did and did not carry. It is archived by dated heading, matching `docs/DONE.md`; there is no version-heading convention in this repository, and this file's name is the only version identifier.

## 2026-08-09 v0.7.1 shipped as `9a960fc2c`, live on 7770 and 7771

### Release identity

- Tag `v0.7.1` points to commit `9a960fc2c00cd6d9d55a523481c58e4585f861e2` on branch `dev/0.7.1` (`fix: the web process publishes only what it measured, and says so when it cannot`, authored 2026-08-09 12:19 PT).

These pids are the landing measurement, not re-measured here — 7770 is off-limits and 7771 is a production instance this work did not restart or probe. "Live on 7770 and 7771" is deployment, not acceptance: the queue's live-server acceptance evidence was never produced (see "Shipped without closure" below).

### What the Daemons monitor rework delivered

The v0.7.1 line landed the daemon-monitor rework — real per-service observability replacing fabricated placeholders — verified against source at this base:

- **Real per-service metrics, including the web process.** Six local services (`indexd`, `statsd`, `jobd`, `statusd`, `watchd`, `approvald` — `yolomux_lib/local_service_projection.py:82`, `yolomux_lib/app.py:593`) report request/completion/error counts, latency, uptime, memory, CPU and restarts from measurements that already existed and were being discarded, through one shared aggregator (M6, `docs/DONE.md`). The YOLOmux web process is the roster's first row.
- **No fabricated zeros.** An unmeasured value renders `—` with its reason code, never `0`. The web process's process metrics say so with reason `web_process_not_observed` (`static_src/js/yolomux/85_debug_panel.js:7607,8052`) because the observer runs *inside* the web process and cannot observe it. The CPU first-sample has no baseline, so `CpuSampler` publishes nothing that cycle and the caller counts the skip with reason `cpu_sample_no_baseline` (`yolomux_lib/stats_current/service.py:1718`) rather than emitting a zero.
- **Superscript partial marker.** A partial count is footnoted with a real `<sup>` marker (`*`) directly after the number so a partial total can never be read as a complete one (`static_src/js/yolomux/85_debug_panel.js:8243-8252`); the qualifying sentence rides in the existing `a11y-only` span for screen readers.
- **No first-poll rebuild.** `refreshDebugSystemViews()` no longer runs `view.innerHTML = ...` to rebuild the whole Daemons view every 5 s poll; it replaces only the regions whose HTML changed and restores focus by a stable key, so an open row keeps its DOM node, focus and scroll across a poll (`static_src/js/yolomux/85_debug_panel.js:8867,9008`).

### Shipped without closure

Two known costs were carried into `v0.7.1` unclosed and are named here so the release record does not read as complete:

- **The `/api/system-status` request-thread cost.** At `v0.7.1` the route built the entire payload on the request thread (`runtime_local_services`, `transcripts_payload`, `copy.deepcopy`), measured at 0.18 s typical and 1.002 s under load. This is **fixed in 0.7.2** by a background snapshot owner (`start_system_status_snapshot_owner` / `system_status_snapshot_response` at `yolomux_lib/app.py:11656,11688`; route at `yolomux_lib/http_routes.py:685`), tracked as `DOIT.p0.v0.7.2.md` F1. It was not fixed in 0.7.1.
- **The interactive-API lane findings.** Five source-reachable findings — a shared 4-thread completion pool and a global 64-slot queue sitting in front of jobd's isolated lanes, so executor-lane isolation is not end-to-end accepted-operation isolation — shipped unaddressed in `v0.7.1`. They are historical source-reachability findings only (never dynamically re-reproduced), owned by `DOIT.p0.interactive-api-lanes.md` and re-audited in `DOIT.p0.v0.7.2.md` F2. None was closed by shipping the tag.

The full completed/open ledger for the daemon-monitor queue that this release carried — 15 of 23 boxes complete, the retained `/tmp` health-history correction, and the 8 open boxes folded to 0.7.2 — is in the `docs/DONE.md` entry `## 2026-08-09 Backend health is observed continuously, retained per port, and shown in the topbar`.
