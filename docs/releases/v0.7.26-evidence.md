# v0.7.26

Landing record for the global release containing the OpenCode observation and terminal interaction work added after `v0.7.25`. The exact tested subject SHA is `f25fb791246f25f3b43a6ecbfb995cf574e9861f`. The final annotated tag target is `v0.7.26^{commit}`.

## Shipped scope

- Native OpenCode processes are identified from operating-system executable identity and exposed as visible per-window status rows without treating model names, shell text, or arbitrary command arguments as agent identity.
- OpenCode TUI captures classify supported working, idle, blocked, and question states through the shared terminal classifier. Permission cards remain blocked and non-typeable; OpenCode is not a structured YO!agent send or auto-approval target.
- OpenCode status reaches statusd, session payloads, YO!stats status, pane tabs, Tabber, popovers, top-bar counts, and shared green/red/yellow status rendering with explicit unavailable handling.
- OpenCode usage is read from its local SQLite database through a read-only, credential-free reader. Completed `step-finish` records emit input, cache-read, and output usage atoms with original timestamps, bounded session attribution, cursor recovery, coverage epochs, and typed unavailable spans.
- OpenCode terminal interaction preserves the native context menu, routes iPad touch scrolling through the shared line-wise terminal owner, sends native PageUp/PageDown sequences, and groups soft-wrapped URLs for hover, context-menu, and underline behavior.
- The generated JavaScript and CSS bundles, prompt captures, architecture inventory, backend tests, browser tests, and Node tests were updated with the implementation.

## Verification

- Focused OpenCode, statusd, YO!stats, application, session, detector, terminal, URL, paging, touch, mock, static-build, architecture-budget, text-shape, Node layout, Python compilation, syntax, and whitespace checks passed during release preparation.
- The canonical `python3 tools/check.py` run was attempted. Its latest run passed the browser lane, end-to-end lane, serial lane, Python compilation, syntax, and whitespace checks. The Node layout lane had one stale assertion that was corrected and passed in a focused rerun. The non-browser lane reported pre-existing shared-worktree and host-process failures, and exact-SHA certification was refused because the candidate was dirty before the release commit.
- Browser tests that depend on historical commits failed because the shared Git worktree metadata pointed at an unavailable worktree directory; this is environment infrastructure rather than OpenCode behavior. The affected historical-fixture tests were not counted as passing.
