# User-interface contract

This page keeps the durable user-visible rules. The selected backend's capability catalog determines which product areas are available. Exact geometry, event ordering, and regression assertions belong in the current browser and Node tests.

## Software updates

- The update notice appears after an eligible `version.yaml` bump reaches `origin/main`; ordinary commits without a higher product version stay silent. The configured major/minor/patch/none preference controls notices, and `none` disables update checks.
- Only an admin can start Update & restart. Confirmation precedes installation, and readonly users cannot submit the mutation. A repeated admin click returns the active job instead of starting another installer.
- The server prepares the exact fetched commit before activation. Dirty, diverged, or changed checkouts remain untouched. Preparation errors keep the current server running and remain visible in job status.
- A browser reload waits for both the target product version and a different Go instance identity. An old server response cannot complete restart polling; unsaved editor changes and active typing continue to defer reload.

## Layout and navigation

- Keep panes and tabs usable across desktop, narrow-window, and touch layouts. Preserve the user's active selection and restored layout when switching between surfaces.
- Pane header buttons and tab-close controls use the same dimensions and styling on mobile, touch, and desktop layouts. Do not enlarge their hit targets or header rows for touch; native touch taps use the same actions as desktop clicks.
- When a tmux session exits outside YOmux, remove its tab and reconcile its pane within five seconds while preserving the saved layout placeholder.
- Session rename accepts one submission while its reply is pending. The submit button visibly disables, the existing tab displays the proposed name, and rejection restores the original name and re-enables submission. Accepted renames preserve the new tab, active pane, and roster when an older roster arrives.
- When a tmux session is renamed outside YOmux, preserve its tab and pane under the new name even if metadata or activity reaches the browser before the roster event.
- A control's label, tooltip, accessibility state, and action must agree. Menus and popovers must work with pointer, keyboard, and focus changes.
- Shared browser code does not imply that every backend supports every route. Hide or disable features according to `/api/capabilities`.

## Terminal and status

- Terminal input, selection, copy, paste, links, and touch gestures must preserve the terminal application's own behavior where it owns the interaction. Keyboard delivery must remain available during resize, attach, and secondary pane updates. Network ping is distinct from native-key-to-visible-character latency.
- Terminal resizing uses native tmux copy-mode reflow. YOmux does not reposition copy cursors during resize; native reflow may move the scrolled viewport, including to the bottom. Navigation from another browser, server, or native tmux client remains authoritative.
- Terminal URL and file-reference discovery stays within the visible viewport and at most eight physical rows per wrapped token. Redraw scheduling does no buffer scans, and a token that crosses the row limit remains unlinked.
- Agent status comes from the selected pane or window. Exclude verified internal Tabber window-view aliases from process attribution so activity stays keyed to the source session. Do not create duplicate rows or carry activity across a reused tmux target.
- A visible Codex `Working (... esc to interrupt)`, `Compacting context (...)`, or `Waiting for background terminal (...)` line is the current working state, even when the idle composer and older command output remain on screen.
- Pane Tabs and Tabber show Play for green working, Pause for yellow completion, and a square Stop for red attention or blocked status when there is only one distinct visible status color, regardless of window count. Single-color symbols have a thin dark outline so their edges remain visible on matching colored tab backgrounds. Red attention, blocked, and unavailable states share one color. Mixed status colors retain segmented circles, including green with red or yellow. Preserve indicator spacing, status badges, accessibility labels, and pulse animation through these transitions.
- Agent windows pulse green while working. A metadata refresh must keep that pulse when a fresh collector sample matches the current session, pane, agent kind, and process instance; metadata expiry alone does not mean work stopped. After a status sample confirms that work stopped and the agent is idle, pulse yellow for the configured workflow transition duration, then keep a steady yellow completion reminder until the user acknowledges it or a new run begins. Yellow means the agent stopped working and the user can type; the animation timer must not remove the reminder.
- The backend owns agent working state. Pane Tabs, Tabber rows in both modes, window controls, and live counters consume the same admitted agent-window snapshot and shared display update. An accepted SSE or activity response updates all mounted indicators and Tabber dates together. A newer unavailable sample must not inherit an earlier working state; metadata and historical activity dates do not override current backend state.
- Detect current requests for user input or approval and blocked/error screens automatically, including untouched and hidden tabs. Show a red `ASK` for a recognized question or approval request and a red `BLK` for a blocker. A queued Codex question may show red `ASK` beside a green working ball because the agent is still running. Match current prompt controls and screen evidence; quoted questions and older output must not create attention.
- Clicking a session Tab or its Pane body, including an already-focused Pane, acknowledges the indicated red/yellow event. A direct window control acknowledges that exact window; a parent session Tab or Pane acknowledges its highest-priority actionable child. Touch taps and real terminal input use the same acknowledgement path. Hover, automatic focus, scrolling, passive terminal reports, and merely leaving a Pane open do not acknowledge attention.
- Acknowledged red/yellow balls and their `ASK`/`BLK` labels immediately turn gray, fade once over the configured status pulse period, and disappear when that interval ends. Acknowledging a queued question leaves its still-working green ball intact. The same unchanged event stays hidden through refresh and reload; a new question, blocker, run, or reused process/pane identity gets its own lifecycle. Acknowledging a marker records that the user saw it and does not answer the question or dismiss the terminal application's prompt.
- Session status markers stay grouped immediately after the status circle and before the session title, and Tabber rows repeat the same status and repository badges shown on Pane Tabs: `BLK` for blocked, `ASK` for a current user question or approval request, including a queued Codex follow-up question, `TEST` while a test command is active, `OFF` while the terminal is disconnected, and `YO` when auto-approval is enabled or offered. Keep the group visible on narrow tabs and avoid repeating these labels after the title.
- Keep the `YO` status marker visible when the backend reports auto-approval enabled or offered. Add the toggle action only when the backend advertises `yolo.auto-approve.v1`; otherwise render the marker read-only. After a toggle, use the server response as the authoritative state and consume `auto_approve_changed` snapshots so other tabs converge without polling. A successful toggle updates the marker without leaving a global status message.
- Notifications identify their target without stealing focus. Repeated notices for the same target should update one visible item. Successful terminal uploads open the numbered action chooser at the pane top-left and do not show a separate yellow Uploaded toast; upload errors and size-limit notices remain visible.

## Finder, Differ, and editor

- Finder and Differ share tree-row, sorting, status, selection, and toolbar behavior. Each surface keeps its own session-file payload; Finder metadata must not change Differ or Repo Diff rows.
- Opening a file editor, preview, or Repo Diff tab through a user action, clicking into it, explicitly reloading it, or editing its content updates that item's Tabber activity date immediately. The activity snapshot keeps the date across browser reloads; restoring an editor automatically during reload does not count as activity, and scrolling does not update activity.
- Tabber applies authoritative tmux session renames to its visible row and click target as soon as the roster update arrives, including renames made by another browser.
- In Advanced mode, right-clicking a file editor, diff editor, or Differ tab opens the shared tab menu with Close. Closing an editor uses the same dirty-file confirmation and buffer cleanup as its close button; closing Differ removes it from the active layout.
- In the simplified Tabber, right-clicking a one-window tmux session offers Kill tmux session. With multiple windows, it offers Kill <window name> in tmux session and Kill entire tmux session (<count> windows). Killing one window preserves the session.
- Tabber starts in the mode saved in Preferences, shared across browsers and preserved through server restarts; users can change it either in General Preferences or with the shared home navigation checkbox immediately before its minimize control. Normal and Advanced default to relative Ago dates and most recent activity first. The Tabber sort menu lists Recent first and selects it by default on a fresh install; saved sort choices continue to persist. After saved browser and URL settings restore, a one-time migration selects and persists Ago without changing the chosen sort order or Finder/Differ preferences; subsequent explicit Date/Ago/None choices persist. Normal mode keeps built-in utility tabs such as YO!info, Finder, Preferences, and file editors in an alphabetized block at the bottom of the roster, including while conversation activity is unavailable; it omits Differ, YO!chat, and YO!agent from selectable rows. On a fresh layout, its first terminal pane selects the conversation window with the newest activity timestamp once the first activity snapshot arrives. Normal and Advanced show the same flat list of tmux windows, including a single-window session only once and each window of a multi-window session at the same level, with matching rounded two-line labels, status markers, dates, and descriptions and no disclosure controls. In Normal mode selecting a row shows its terminal in the sole content pane, selecting another row switches that pane, and clicking the selected row again hides it. The left Tabber sidebar collapses automatically when the Dockview host cannot fit its measured minimum width beside the content pane; a topbar button remains available to show or hide it, and a manually hidden sidebar stays hidden when the window is resized. Advanced preserves multi-pane behavior. Its toolbar keeps Lookback, sort, and Ago; the sort selector fits its longest option, and there are no expand-all or collapse-all controls. Advanced exposes Differ, YO!chat, and YO!agent through the regular pane controls, and, on each Normal-to-Advanced transition, groups Finder, Differ, and Tabber from left to right with Finder selected. The Normal-mode home strip hides the Tabber pane tab and keeps its Advanced checkbox and minimize control visible; Advanced shows the pane tab again. Normal mode keeps the YOmux brand, global topbar menus, Search, language, latency, and utility controls visible alongside the Tabber icon, and hides the topbar activity counts shown in Advanced mode, which can reopen the sidebar or show Tabber in the single content pane. The Tabber New Chat control opens a popup with the standard and dangerously-auto-approved Claude and Codex launch choices plus the configured Shell choices, rather than opening File; Escape returns focus to the New Chat button or Tabber launcher. When the browser is too narrow to fit the sidebar beside the measured minimum content width, Normal mode removes the sidebar and keeps one content pane; its topbar icon opens Tabber in that pane and toggles back to the selected terminal. The transition orders all real live tmux sessions by newest activity, excludes internal window-view aliases, and uses the existing measured minimum width to choose one terminal pane or two equal-width panes. Two panes receive contiguous balanced session groups, with an extra session on the left; the selected session remains active in its group and the other group selects its newest session. A selected window view retains its terminal identity in place of its source session. Zero sessions retain the empty content pane. Dividers remain movable; later resizing uses the existing responsive policy without reapplying this arrangement. New Chat is a blue, rounded compose-icon button; Search uses a circular, theme-aware control that opens the shared Quick Open palette. New chats use the next available numeric tmux name. Each window initially shows that name; its first conversation title or first user message supplies a short description. Window-owned descriptions survive reloads, server restarts, and tmux renames. Rename Description edits the clicked window and permanently overrides automatic naming, including an intentionally empty description; Rename tmux edits the containing session without changing descriptions. Normal and Advanced use the same flat, rounded, theme-aware two-line row presentation for conversation titles, status markers, dates, and descriptions: the first has the shared status marker before the agent symbol, then the tmux name and right-aligned muted last-modified date; the second has a truncated conversation description. They retain unacknowledged attention when no transcript date is available. Normal content panes hold one item and hide their tab strips, including terminals and file editors. The home navigation strip and its controls stay available in both modes, and its Advanced checkbox reflects the current mode in either theme. The Tabber content toolbar does not duplicate the checkbox. The singleton left Tabber owns select/unselect for all content items, with zero or one selected content pane. Saved layouts, direct mutations, file/tool open routes, and Dockview readback share this singleton and one-pane admission policy. Deselection and switching retain registered buffers, pooled panels, terminal identities, attention, and view state. The empty Normal pane hides the drag-and-drop prompt because Normal mode blocks tab dragging. Advanced restores unrestricted tab strips and pane behavior. Normal mode blocks tab dragging through native, fallback, and touch paths and disables manual split, move, fill, expand, and layout commands; the Tabber minimize control hides the sidebar. Mouse and keyboard selection share the same toggle owner. Explicit URL chat targets use the same one-pane policy; file and other nonterminal targets remain registered when selection changes.
- In Recent mode, automatic sorting uses the latest activity at most once every 10 seconds; timestamps and status keep updating between sorts. Explicit sort-mode changes apply immediately. Accepted terminal keyboard and paste input counts as activity even without echoed output; mouse tracking and terminal protocol reports do not. Terminal input, editor changes, and Repo Diff engagement are recorded by the server and returned in the existing activity snapshot; their dates also update locally immediately. Session activity includes its newest window activity. Activity refreshes retain the displayed order of surviving Tabber rows while the pointer is anywhere inside its pane. Update working/attention markers, selection, descriptions, and dates in place; append new rows and reconcile exited sessions through the shared flat-row renderer. Pointer exit schedules one refresh with the latest data when the sort interval is due; immediate reentry cancels it. Active row popovers retain their anchor and defer reordering without stopping child status/date updates. Initial rendering and explicit sort actions apply immediately. Hover state is pane-scoped, disposed with the panel, and never persisted. English relative dates use `min ago`, `hour/hours ago`, and `day/days ago`; sub-minute and older-age handling stays on the shared formatter.
- A saved server Tabber mode takes precedence over stale browser storage in either direction. Legacy browser Advanced mode migrates only when the server confirms that no mode preference was stored; startup cannot overwrite an explicit Normal preference.
- When a tmux session has multiple windows, each Normal row identifies the specific window as `[session] <index>:<command>` and uses that window's own activity timestamp for ordering and its displayed date. If timestamps are unavailable or equal, keep that session's windows together in index order rather than implying an activity difference.
- Selecting a terminal tab immediately clears the previous tab highlight and selects the new tab in a pending color halfway between the current theme's inactive and active tab colors. Show and focus its terminal immediately so keyboard input can start without waiting for Finder or Differ work. Apply the normal active theme color after xterm consumes output queued at activation, renders the current viewport, and crosses a paint opportunity; continuous output does not keep the tab pending. Session-side synchronization and file-surface activation run after the terminal has had a paint opportunity; superseded updates stop before rendering. Hidden Differ retains the latest payload and renders it when selected, with visible tree updates yielding to input.
- Terminal activation shares one pending parse fence, viewport repaint, reference-underline update, and attention update per terminal. Resize ownership renewal is independent of Finder generations and coalesces pointer and tab activation requests. An unchanged ownership claim still reconciles competing tmux clients but does not repaint xterm, resize the PTY, or send SIGWINCH. Warm tab highlight and focus have a p95 budget below 50 ms; terminal paint and native keyboard echo have a p95 budget below 100 ms. Measure cold connections separately, using trusted browser input and real xterm on the selected backend.
- Authoritative tree replacements retire obsolete rows, placeholders, and child wrappers before replacement rows become visible. Keep expanded children and failed-listing errors when their directory remains present. Repository stream chunks preserve arrival order and leave unchanged previously published rows and controls intact. A delayed directory expansion cannot attach children after that row becomes a file.
- Collapsing a Finder directory preserves its nested expansion state across reload. Reopening the parent restores those descendants through the shared listing and expansion lifecycle.
- Finder refreshes and asynchronous expansion preserve the viewport. Native scrolling owns the viewport throughout a gesture and its settling motion; an older refresh cannot rewind it or transfer its saved position to a replacement tree.
- Finder listing and metadata refreshes preserve all rows, automatic expansion, selection, and column geometry. Metadata updates must finish for the current mode and session even when the user changes either during a refresh; an older transaction cannot replace the current target.
- An indexed Finder directory with partial coverage shows a `!` badge. Hovering it states the indexed count, configured per-root file limit, and whether the crawl stopped at the file-count or snapshot-storage budget; the tooltip must not describe a storage cap as a file-count cap.
- Finder index errors show the backend's error detail in the directory badge tooltip. Reaching the configured per-root file limit publishes a searchable partial index; a traversal error during refresh retains the prior searchable snapshot and reports the failure.
- Finder directory totals count each absolute file path once. When session payloads report that path more than once, use the record with the newest modification time for line totals, break ties by session name, and retain agent attribution from every record.
- If a restored Finder directory expansion fails to load, stop its spinner, show the listing error, and remove that expansion from saved layout state. Retry uses the shared directory-listing path.
- Read-only users can open a repository's Repo Diff tab directly, expand commits and the Dirty row, and view file comparisons without editing. The collapsed Dirty summary stays on one line from first paint and keeps its fields aligned with commit rows while history statistics load. General filesystem actions retain their backend permissions.
- Repo Diff commit rows use a 20 CSS-pixel minimum height, no vertical padding, and a 1:1 line height. Metadata columns size to their content to preserve room for refs and subjects. Dates and file-change summaries use 80% of row text size; compact signature codes have plain-language tooltips and accessible labels.
- Show file content as soon as the bounded read completes; optional Git decoration may arrive later. Keep authorization and filesystem failures visible instead of painting stale or replacement content.
- Text editing stays distinct from preview. Markdown ViewEdit uses the supported ProseMirror path; if parsing fails, keep the source preview read-only and show the error. Saving, mode changes, close, and blur must not discard pending edits.
- In file-editor Markdown previews, relative and root-relative file links open through the YOmux editor from both clicks and link context menus; explicit external links open in a browser tab.
- Zoomed images and diagrams can be panned by dragging their content; the pan gesture continues across pointer movement outside the viewport and ends on release or cancellation.
- Uploads and pasted images use the active editor's file-relative path and the original selection or caret captured for that operation.

- Finder Preferences defaults Maximum indexed files to 1,000,000; its number field leaves enough room for all seven digits and the native spinner.
- Hidden Finder, Differ, and Quick Open consumers stop index-status polling immediately. Hidden terminal aliases stop transcript and summary streams; completed summaries remain cached until explicitly requested again. Window aliases resolve metadata and attention by stable physical window identity after reindexing.
- Quick Open keeps the previous indexed snapshot searchable during refresh. Its terminal search summary clears the indexing indicator, reports partial coverage, and marks retained results stale after a failed refresh, including when the generation and cursor stay unchanged. Publication refreshes an open query without requiring another keystroke. A server restart preserves searchable rows, and replayed progress from an older worker cannot restart a settled search.
- Filename queries match independent whitespace-separated tokens. Capped directory search results retain the strongest whole-name matches across the complete directory. Filtered, truncated, and superseded listings cannot clear unrelated deletion tombstones.
- Quick Open ranks an exact filename match above recent and partial matches. The numbered terminal upload action chooser avoids visible toast notifications where space allows and stays above them if no clear placement exists.

## Statistics and diagnostics

- Render only values supplied by the active backend. Keep loading, pending, unavailable, failed, and valid no-data states distinct.
- YO!stats pop-out opens a live window containing only one YO!stats pane, without the YOmux menu bar, Finder/Differ/Tabber panes, the minimize control, or another pop-out control. Its buttons and chart range controls remain interactive, and it omits the temporary viewport-diagnostics overlay; the source tab leaves the layout while detached and returns to its prior slot and active state when the pop-out closes or the source page unloads.
- Range and resolution follow server capabilities and accepted snapshots. The browser does not aggregate data or fabricate missing values.
- YO!stats range dragging previews only the thumb and range label. Successful release, including release outside the slider, commits the selection once and immediately requests its history. Cancellation, unexpected capture loss, focus loss, hiding, or disposal restores the committed range and preserves its resolution and zoom. Delayed change or capture-loss events do not commit again. Keyboard range input commits immediately.
- YO!stats cost reports show the top 16 models and agents and up to 32 pricing evidence rows; aggregate totals still include omitted details, and omission counts remain visible.
- Explicit Retry starts a fresh full history request immediately. Keep loading, pending, ready, and error states distinct; silent history requests must end in a visible error, and a later valid response can restore ready state.
- System -> Daemons exposes the shared capability-backed Range and Resolution controls; changes apply to the shared YO!stats history selection.
- Graph hover lines, selection highlights, and drag zoom use the shared interaction owner. The chart under the pointer owns its gray vertical line and zoom domain throughout the gesture.
- Graphs CPU shows cumulative host-process CPU with total System CPU and readable per-process host series; keep per-process daemon CPU lines out of that chart. If the host process census is partial, retain measured CPU and RSS series and visibly mark the breakdown partial; unreadable processes remain unknown gaps, never zeros. System -> Daemons shows Go process CPU as a comparison line alongside runtime-owner occupancy, never as another stacked component; process RSS stays in its separate memory chart.
- Graphs places the hidden-by-default Space used % chart immediately after GPU memory. When enabled, it plots one 0–100% line for each filesystem listed by the latest `df -kP` sample, sampled every 5 minutes, and labels each line with its mountpoint; history stays visible for those paths, while no longer listed paths disappear from the chart. Missing or inaccessible capacity samples remain gaps in that filesystem's line.
- Place the Refill last 24 hours action after all Graphs chart cards.
- Go process history distinguishes host, boot, PID, process start, and owner so concurrent instances and restarted processes do not merge. Labels and details show PID, port, executable, and parent PID when available. Keep older samples without recoverable process identity visible as legacy; do not assign them a current PID. Process CPU and elapsed collector occupancy remain separate measurements.
- System -> Daemons labels restarts without a recorded graceful shutdown. The Go backend records one only after it observes a termination signal, closes its managed schedulers, drains HTTP, and completes tracked stats-recorder and writer shutdown without an error; collector and database close or persistence failures are outside this count whether or not they appear in separate diagnostics. This is not a crash detector. An unknown launch reason affects classification only and does not mean retained restart totals were reset.
- Daemons charts use cumulative filled areas with distinct color/pattern pairs and fully visible, wrapping legends. Repeated colors use vertical lines or dots that remain visible in the legend; do not use horizontal or diagonal hatch marks. Cards grow with their legends instead of scrolling or clipping them. Nested occupancy measurements must not be presented as additional independent work.
- Use bright, fully opaque fills for CPU, System memory, Daemons Load, Daemon memory, and Go memory detail areas. Each plotted area and its legend swatch must use identical base colors and infill marks, with no opacity reduction on the area, swatch, pattern, or ancestor. Paint comparison lines above those fills. Keep each same-named `yomux-go` host CPU and RSS process separate, with its PID in the legend label.
- Go memory diagnostics show runtime memory classes and sampled retained allocation stacks as cumulative filled areas, separately from process RSS. Size both plots to fill the available card width with a readable height, and keep their wrapping legends visible. Label memory chart axes in bytes and capture time, and make each complete sample's class values available on hover. Plot individual stack history only when its stack key appears in every retained capture; include a short key in each legend label and the full stack in its title because the backend retains only twelve ranked stacks per capture. Rank individual stacks and show capture age, process identity, units, unavailable reasons, and retained versus cumulative allocation bytes; never label sampled stacks as exact struct sizes or claim they account for native memory. Heap capture is bounded and restricted to administrators.
- Diagnostics must identify unavailable backend data instead of inventing Python service rows for Go.

- Agent stats provides one administrator-only "Refill last 24 hours" control beside its chart controls. Confirm with "Refill the last 24 hours?", the CPU/slowness/deleted-history warning in prominent theme-aware red, and Cancel/Refill actions. Freeze the preceding 24-hour window at acceptance; continue collecting new activity and preserve recorded Run/Ask/Idle history.
- During refill, disable its button and replace session/model token charts and usage/cost with "Refilling agent history… Please wait." Show actual reading/rebuilding phases without percentages. Leaving, reopening, reloading, and other tabs attach to the same host job. Completion reports success or names unavailable history sources; failed scans leave previous data intact and offer Try again through the same confirmation. Preserve the lightweight chart Retry action.

## Verification

- Reproduce the reported URL, layout, theme, or pointer state before changing a visual rule.
- Use real Chromium for geometry, focus, keyboard, touch, and drag behavior. Assert the interaction state as well as the final layout when an intermediate preview or held state matters.
- Rebuild `static/` after frontend source edits. A live-port fix requires a restart and proof that the server serves the rebuilt bundle.
- Keep this page short. Move exact values, implementation details, and test matrices into source comments or focused tests so this document does not become a second copy of the code.
- Markdown ViewEditor preserves standalone raw HTML images inside and outside details blocks. Split scrolling uses source anchors across decoded tall images and details expansion; headings retain their original source lines.
