# User-interface contract

This page keeps the durable user-visible rules. The selected backend's capability catalog determines which product areas are available. Exact geometry, event ordering, and regression assertions belong in the current browser and Node tests.

## Supported runtime

Go owns the supported runtime. Shared browser shells and saved layout aliases do not establish that a server feature exists. Search & Runs event search and run history, background AI activity summaries, and watched pull requests are retired. Native chat, agent conversations, terminal transcripts, local Finder/Git views, and per-session event logs retain their own capability and route owners. Mock interactive clients retain complete Unicode characters during key-by-key input, matching the real client composer. The current route and retirement inventory is in [`GO_MIGRATION.md`](../../GO_MIGRATION.md).

## Authentication setup

- On first Go startup, create `auth.yaml` in the configured directory with mode 0600, a generated admin password, and the account entry commented out. The first-run page points to this file and tells the user to uncomment the existing admin entry; it never displays the generated password. Preserve any existing auth file. Existing empty or placeholder configurations receive instructions for adding an admin account or replacing placeholder credentials instead of assuming a generated account exists.

## Software updates

- The update notice appears after an eligible `version.yaml` bump reaches `origin/main`; ordinary commits without a higher product version stay silent. The configured major/minor/patch/none preference controls notices, and `none` disables update checks.
- Only an admin can start Update & restart. Confirmation precedes installation, and readonly users cannot submit the mutation. A repeated admin click returns the active job instead of starting another installer.
- The server prepares the exact fetched commit before activation. Dirty, diverged, or changed checkouts remain untouched. Preparation errors keep the current server running and remain visible in job status.
- A browser reload waits for both the target product version and a different Go instance identity. An old server response cannot complete restart polling; unsaved editor changes and active typing continue to defer reload.

## Layout and navigation

- An empty tmux roster must still load the application shell for administrators and read-only users. Initial session and recent-session inventories are JSON arrays, including when there are no sessions.
- The top-right Refresh control repaints every visible terminal and asks tmux to redraw the full screen for each visible session without reloading the browser page.
- Back and Forward traverse one global, unique list of visited tab instances across all panes. Explicit tab activation and pane-body focus move that tab to the end; traversal preserves recency and never reopens a closed tab. Clicking after Back retains all other surviving entries. History lasts until page reload and retains every visited open tab, including distinct copies. In Normal mode, traversal reveals a visited tab even when it is registered outside the current single-pane layout, without recording another visit.
- Closing the focused tab selects and focuses the globally most recently visited survivor, even after Back; closing a background tab preserves focus. Reconcile batch removals before selecting a replacement, including external tmux exits and tab-cap eviction. If no visited tab survives, choose the first remaining tab in layout order. Moves, reorder, pinning, and rendering do not record visits; renames replace IDs in place. Explicit navigation and closure focus content with automatic cursor following disabled, and stale callbacks cannot override newer focus. A terminal that regains keyboard focus keeps its pane focus when an older blur event arrives; blur events from replaced terminal elements cannot clear the replacement's focus. A terminal reconnect restores its pane focus only when that terminal still holds keyboard focus and no newer navigation has superseded it.
- Finder deletion keeps unsaved buffers open while requests are pending and after failures. A successful deletion retains dirty content as missing on disk, including edits typed while the request was pending; only successfully deleted clean tabs close.

- Keep panes and tabs usable across desktop, narrow-window, and touch layouts. Preserve the user's active selection and restored layout when switching between surfaces.
- A settings save preserves the layout and focused pane selected when its response arrives. Navigation admitted while the request is in flight must remain visible after the settings apply.
- An open settings menu updates its checked markers as soon as the selected setting applies locally. Pending persistence does not leave the previous value checked. Completion and failure refresh the same menu without closing it or losing the focused command.
- When switching Tabber from Normal to Advanced, retain Tabber as the selected home tab if it was active before the switch.
- Pane header buttons and tab-close controls use the same dimensions and styling on mobile, touch, and desktop layouts. Do not enlarge their hit targets or header rows for touch; native touch taps use the same actions as desktop clicks.
- When a tmux session exits outside YOmux, remove its tab and reconcile its pane within five seconds while preserving the saved layout placeholder.
- Direct terminal URLs update window controls, tab labels, and Info Bars when initially loading metadata finishes, including when Tabber is absent. Reconnection or event loss restores the same metadata without navigation or manual refresh.
- Session rename accepts one submission while its reply is pending. The submit button visibly disables, the existing tab displays the proposed name, and rejection restores the original name and re-enables submission. Accepted renames preserve the new tab, active pane, and roster when an older roster arrives.
- When a tmux session is renamed outside YOmux, preserve its tab and pane under the new name even if metadata or activity reaches the browser before the roster event.
- A control's label, tooltip, accessibility state, and action must agree. Menus and popovers must work with pointer, keyboard, and focus changes. Checked actions that keep a menu open refresh their state without closing its submenu or losing focus.
- The Tabber New Chat menu escapes pane clipping while remaining anchored to its trigger and bounded by the visible viewport.
- Shared browser code does not imply that every backend supports every route. Hide or disable features according to `/api/capabilities`.

## Finder, Differ, and editor

File pop-out lives in the tab header beside the add-tab button. Text and PDF tabs open as live detached tabs. Other supported file previews use a detached preview window.

The Δ and line-number # controls have a visible button surface at rest, with hover descriptions and clear active styling. Center Δ in its button. While the review is active, show the range, Previous change, Next change, and New diff in a separate row below the main toolbar. Use arrow icons with hover descriptions and accessible labels for navigation. Label the baseline reset button New diff. The fixed Since review started baseline survives rolling-history pruning; Last 1, 5, 15, or 30 min changes the comparison in place without resetting selection, caret, scroll, or undo. New diff captures saved disk contents without writing, and ending a review removes its markings. Preview shows current document content without diff markup; Split aligns with current source lines rather than deleted-line widget heights.

A review belongs to one browser and watched file, including verified renames and atomic replacements. It records observed saved versions from tracking start, not writer attribution or every write. Keep its fixed baseline independent from a maximum of 32 rolling snapshots, retain the last observed snapshot at or before the rolling cutoff, and report the earliest available time when trimming loses coverage. Limit text to 1 MiB per file and review history to 64 MiB per server. Trim rolling snapshots before rejecting a new fixed baseline. End reviews on watch lease expiry or server restart; reconnect across browser reload while the lease survives. Flush pending input before applying external disk updates. For a dirty text editor, compare its saved baseline, current draft, and latest disk text. Apply compatible changes to the draft and use the ordinary save policy. Retry a disk read superseded by a newer observation and keep the draft without a dialog if no valid overlap result is available.
